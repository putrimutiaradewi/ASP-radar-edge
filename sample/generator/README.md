# ASTERIX PCAP Generator for Indonesian Airports

Generates ASTERIX surveillance traffic (CAT019, CAT020, CAT021, CAT023,
CAT247) around five Indonesian airports and exports it as PCAP files,
for testing an ATC ASTERIX decoder.

The generated records replicate the **real Juanda (WARR) surveillance
feed** structure exactly: the same category set, the same per-variant
FSPECs and record lengths (CAT021 ed 0.26 with 4 equipage variants,
CAT020 ed 1.5 with 3 variants incl. the 30-byte Reserved Expansion,
CAT019's 16-remote-sensor status block), the same SAC/SIC scheme
(ADS-B: 0/181, MLAT: 1/1), the same multicast transport
(ADS-B: 192.168.30.92:44180 → 239.200.2.2:8700, TTL 63;
MLAT: 192.168.30.102:55031 → 239.200.2.2:8600, TTL 7) and the same
update rates (2 Hz ADS-B position, 1 Hz MLAT target/status, CAT023
every 2 s per report type, CAT247 every 60 s).

This is a **simulation only** — no real surveillance data is replayed —
but every record is a spec-shaped, correctly bit-packed ASTERIX message
(real FSPEC, real data items, real variable-length records), wrapped in
genuine Ethernet/IPv4/UDP frames with correct checksums, inside a
standard libpcap file that opens directly in Wireshark.

Legacy categories (CAT034, CAT048, CAT062, CAT063) remain available via
`--categories` but are no longer generated by default, since they do
not appear in the real feed.

Requires only the Python 3.10+ standard library — no third-party
dependencies to run the generator itself (the test suite is also
stdlib-only; `scapy` was used only to *validate* the output during
development and is not required to run this project).

## Quick start

```bash
python3 main.py
```

This generates the 5 real-feed categories for all 5 airports (20
aircraft each, 5 minute scenarios) under `output/<ICAO>/catXXX.pcap`.

## Options

Generate **everything** — all 5 airports (WARR, WAHS, WIII, WAHI, WADD,
matching the storage-service `airports` seed) x all 5 real-feed
categories (cat019, cat020, cat021, cat023, cat247):

```bash
python3 main.py \
    --airports WIII WARR WAHS WAHI WADD \
    --categories cat019 cat020 cat021 cat023 cat247 \
    --aircraft 50 \
    --duration 600 \
    --departure-ratio 0.6 \
    --radius-nm 30 \
    --seed 7 \
    --output-dir output
```

(Both `--airports` and `--categories` already default to that complete
set, so the fully-explicit command above is equivalent to
`python3 main.py --aircraft 50 --duration 600 --departure-ratio 0.6 --seed 7`.)

This writes 25 files: `output/<ICAO>/cat019.pcap` ... `cat247.pcap`
for each of the five airports.

| Flag | Description | Default |
|---|---|---|
| `--airports` | ICAO codes to generate (WIII, WARR, WAHS, WAHI, WADD) | all 5 |
| `--categories` | Category modules to generate (cat019/020/021/023/247, plus legacy cat034/048/062/063) | the 5 real-feed categories |
| `--aircraft` | Number of simulated aircraft per airport | 20 |
| `--duration` | Scenario length in seconds | 300 |
| `--departure-ratio` | Fraction of aircraft that depart (rest arrive) | 0.5 |
| `--radius-nm` | Arrivals spawn within this radius (NM) of the airport; departures always start at the airport itself | 30.0 |
| `--seed` | RNG seed for reproducible scenarios | 42 |
| `--output-dir` | Root output directory | output |
| `--src-ip/--dst-ip/--src-port/--dst-port` | Override the UDP/IPv4 transport for all streams | real feed transport (ADS-B: 192.168.30.92:44180 → 239.200.2.2:8700, MLAT: 192.168.30.102:55031 → 239.200.2.2:8600) |
| `--no-holding` | Disable holding-pattern behaviour | holding enabled |
| `--no-missed-approach` | Disable missed-approach / go-around behaviour | enabled |

You can also drive the generator programmatically:

```python
from config import SimulationSettings
from main import generate_all

settings = SimulationSettings(airports=["WADD"], num_aircraft=100, duration_s=1800)
generate_all(settings)
```

Generate traffic for one specific airport with:

```bash
python3 main.py --airports WARR --aircraft 30 --duration 600
```

All positions (targets, MLAT reference point, CAT020 cartesian
coordinates) are derived from that airport's reference lat/lon.

## Replaying the output (pcapreplay.py)

Use `../pcapreplay.py` (requires `scapy` + `progressbar`) to feed a
generated PCAP into the aeroswarm ASTERIX decoder as live UDP traffic.

**Replay the `combined.pcap`** — the generator writes one per airport
containing *all* categories in true chronological order, exactly like
a real multi-stream capture:

```bash
# the full multi-category feed on one timeline, real-time speed
python ../pcapreplay.py --asterix-replay -f output/WARR/combined.pcap -t 127.0.0.1 -p 41234

# 2x faster
python ../pcapreplay.py --asterix-replay -f output/WARR/combined.pcap -t 127.0.0.1 -p 41234 -s 2
```

Do **not** replay the per-category files as parallel background
processes (`for f in *.pcap; do ... & done`): each replay starts its
clock at its own file's first packet, so the streams drift apart and a
track receives, say, CAT021 "airborne, 220 kt" interleaved with a
time-shifted CAT020 "parked, 0 kt" — producing sawtooth speed/altitude
charts in the UI. The per-category files are for decoder testing of a
single category (`-f output/WARR/cat021.pcap` alone is fine).

`--asterix-replay` extracts the ASTERIX UDP payloads from the pcap and
re-sends them to `-t host -p port`, preserving the original packet
timing (scaled by `-s`, or `-Q` to send everything at once).

## Project layout

```
asterix-generator/
  encoder/            # one module per ASTERIX category (binary encoding)
    common.py         # shared FSPEC / time / position / IA5 / checksum-free helpers
    cat019.py .. cat247.py   # real-feed categories (+ legacy cat034/048/062/063)
  simulation/
    airport.py        # the 5 Indonesian airports (lat/lon/runway heading/SAC-SIC)
    aircraft.py        # Aircraft dataclass, FlightPhase enum, Indonesian airline/callsign generator
    movement.py         # per-second kinematics + flight-phase state machine
    scenario.py          # builds an aircraft population and steps the whole simulation
  pcap/
    writer.py           # Ethernet/IPv4/UDP framing + real checksums + libpcap writer
  config.py              # SimulationSettings (the generator's public configuration surface)
  main.py                 # CLI entry point / orchestrator
  tests/                   # unit tests (unittest, stdlib only)
```

## What's simulated

Each aircraft moves through a realistic flight-phase sequence, updated
once per second, governed by a custom physics-engine to ensure accurate
kinematics:

* **Departures:** Spawn at realistic named locations (parking stands,
  aprons, taxiways, runway thresholds). Taxi-out -> takeoff -> climb -> cruise.
* **Arrivals:** Spawn at STAR entry fixes, holding fixes, or final approach
  fixes (with proper ±1 NM jitter to avoid clustering). Cruise (inbound) ->
  descent -> [optional holding] -> approach -> landing -> taxi-in -> parked.
* **Missed approach:** a small percentage of landings go around and
  re-enter the approach sequence.

**Physics Dynamics:**
- **Ground speed and heading** are rigorously derived from actual position displacement vectors each tick.
- **Speeds and vertical rates** match real aircraft performance envelopes (e.g., taxi 10–20 kt, takeoff roll 0→160 kt, climb 220/450 kt, cruise 420–480 kt).
- **Smooth heading transitions:** Heading changes are clamped to a max rate of 3°/s (airborne) or 5°/s (ground) to emulate real aircraft turning behavior.
- **Separation validation:** Ensures airborne aircraft do not overlap during spawn (minimum 2 NM spacing) and monitors tight proximity in-flight.

Position is propagated with real great-circle navigation (destination
point from track + ground speed) and altitude via vertical rate. Since
the real ADS-B feed reports positions twice per second while the
simulation ticks once per second, sub-second reports carry positions
extrapolated along the current track — consecutive records genuinely
move, as in the real feed. CAT020's cartesian position (I020/042) is
computed relative to each airport's MLAT reference point, and CAT020
is only emitted for targets inside MLAT coverage (15 NM, below
10 000 ft), matching how the real MLAT system behaves.

Aircraft are drawn from real Indonesian airline ICAO prefixes (Garuda
Indonesia/GIA, Citilink/CTV, Lion Air/LNI, Batik Air/BTK, Super Air
Jet/SJV, Pelita Air/PAS, AirAsia Indonesia/AWQ) with randomly generated
flight numbers, ICAO 24-bit addresses and Mode 3/A squawks.

The system-status categories are independent of aircraft activity and
follow the real feed's cadence: CAT019 (MLAT system status incl. the
16-remote-sensor block) every second, CAT023's two report types
(ground station + service status) every 2 seconds each, and CAT247
(category version report: CAT021 v0.26, CAT023 v1.2, CAT247 v1.2)
every 60 seconds. Legacy CAT034/063 use `ground_status_interval_s`
(default 10 s) when explicitly requested.

## Running the tests

```bash
python3 -m unittest discover -s tests -v
```

54 unit tests cover: FSPEC bit-packing, position/time/IA5 round-trips,
per-category record structural validity — including that every variant's
FSPEC and record length are byte-identical to the real feed's — the
flight-phase state machine, and the PCAP/Ethernet/IPv4/UDP framing
(including checksum correctness).

A built-in data integrity validator also runs during generation to catch
inconsistencies like zero-speed teleportation or invalid headings.

## Extending to another category

1. Add `encoder/catXXX.py` with an `encode_catXXX_record(...)` function
   that returns `wrap_record(CATEGORY, build_record(items))` where
   `items` is an ordered list of `(is_present, encoded_bytes)` tuples
   (see any existing encoder for the pattern).
2. Add `"catXXX"` to `ALL_CATEGORIES` in `config.py`.
3. Wire it into `generate_airport()` in `main.py` (aircraft-driven
   categories loop over `active_aircraft`; ground/sensor categories
   use the periodic block).

## Notes on feed fidelity

The default encoders (cat019/020/021/023/247) were built by decoding
the real Juanda surveillance capture record-by-record: each variant's
data item set, FSPEC (including the feed's fixed-width FSPEC padding),
item encodings/scales (e.g. WGS-84 positions at LSB 180/2^25) and even
the feed's quirks (CAT020's 30-byte Reserved Expansion with an embedded
timestamp, the all-zero contributing-receiver masks, IP ident always 0)
are replicated. A decoder that parses the real feed will parse these
files identically — item presence, record lengths and value scales all
match. Dynamic values (positions, callsigns, addresses, times) come
from the simulation; constant/opaque fields carry the exact byte values
observed in the real feed. Extending an encoder with additional data
items only requires appending more `(present, bytes)` tuples to its
`items` list.

**A note on CAT048** (legacy): EUROCONTROL CAT048 (Monoradar Target Reports) does not natively encode ground speed or heading (velocity vectors) in its base target reports without specific optional items. Thus, visualising pure CAT048 data in an ATC system may correctly display 0 kt / 0° until fused into a system track (CAT062) by a tracker.
